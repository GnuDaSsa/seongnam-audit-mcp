# 감사사례 검색 벤치마크

사용자가 업무를 설명했을 때 비교할 만한 **알려진 공식 사례**가 첫 다섯 건에 들어오는지, 범위 밖이거나 정보가 부족한 질문에 무관한 사례를 붙이는지 측정한다. `city-retrieval-v1`에는 개발군 20문항과 보류군 20문항이 있다. 두 군 모두 사례 검색 16문항과 결과가 없어야 하는 질문 4문항으로 구성했다. 검색 대상은 공개판과 같은 시청 사례다. 문항의 금액이나 사실을 바탕으로 현재 사용자의 업무가 위법하다고 판정하는 평가는 수행하지 않는다.

## 실행

로컬 비교에는 [README의 공식 자료 및 모델 준비 절차](../README.md)가 필요하다. 원격 조회는 자료나 모델 다운로드 없이 실행할 수 있다. 프로그램은 Node.js 22 이상에서 동작한다.

```sh
node --test tests/benchmark.test.mjs
node benchmark.mjs --mode compare --split development --output development-results.json
node benchmark.mjs --mode compare --split holdout --output holdout-results.json
node benchmark.mjs --mode compare --suite reserve-v1 --output reserve-results.json
node benchmark.mjs --mode live --split all --output production-results.json
node benchmark.mjs --mode live --suite reserve-v1 --output production-reserve-results.json
```

`--mode compare`는 같은 시청 스냅샷·검색 필터·키워드 후보 집합에서 용어 검색만 한 결과와 모델을 더해 순서를 다시 매긴 결과를 비교한다. `--mode live`는 운영 주소의 실제 MCP 도구를 호출한다. 별도 배포본을 확인할 때만 `--url https://호스트/public-mcp`를 지정한다. 두 모드 모두 정답 ID나 인용문을 첫 검색 호출에 보내지 않는다.

## 질문과 정답

[질문](../benchmarks/questions.json)에는 업무 상황과 명시한 필터만 담았다. [판정표](../benchmarks/judgments.json)는 공식 게시물의 사건 ID, 감사 연도, 대상 기관, 분야, 원문 위치, 짧은 확인 문구와 주소를 담는다. 판정표는 검색과 독립적으로, 시청 공식 게시물 본문에서 확인한 사실을 바탕으로 먼저 작성했다. 32개 사례는 기존 하네스의 고정 사례와도 겹치지 않는다. 개발군에서 검색을 조정한 뒤 보류군을 열었다. 이미 공개된 두 군은 이후 버전에서는 회귀 검사로 사용한다. 독립적인 새 측정에는 이전 개발에 쓰지 않은 질문·지적 사례를 함께 새 버전으로 보존해야 한다.

질문·정답을 바꾸면 [설정](../benchmarks/config.json)에 고정한 SHA-256과의 차이로 실행이 중단된다. 자료 갱신 시 원문이 달라지면 기존 해시와 측정 기록을 남기고 공식 원문을 다시 검토한다. 근거에 포함된 연도는 감사 연도다.

## 판정

| 항목 | 계산 | 개발군과 보류군 각각의 최소 기준 |
|---|---|---|
| Hit@1 | 알려진 사례가 첫 번째에 나온 양성 문항 수 ÷ 양성 문항 수 | 50% |
| Hit@3 | 알려진 사례가 첫 세 건에 나온 양성 문항 수 ÷ 양성 문항 수 | 75% |
| MRR@5 | 첫 알려진 사례 순위의 역수 평균. 첫 다섯 건에 없으면 0 | 0.65 |
| 기권 정확도 | 업무 불특정·범위 밖·빈 필터 문항에서 결과를 비운 횟수 ÷ 해당 문항 수 | 100% |
| 원문 대조 | 등록된 모든 양성 근거를 해당 사건·위치에서 다시 읽고 최종 검증까지 통과한 문항 비율 | 100% |

Hit@5도 함께 기록한다. 각 질문에 답할 수 있는 모든 공개 사례를 조사해 표기한 전수 정답셋은 아니다. 고정 사례가 빠지고 다른 유사 사례가 반환된 문항은 결과 파일의 상위 ID를 확인해야 한다. 최초 검색의 해당 사례가 연도·기관·공식 URL·근거 위치까지 맞아야 순위 점수를 준다. 이와 별도로, 첫 검색에서 빠진 사례도 원문 대조 분모에 포함한다. 제출된 증거는 해시·원문 위치·인용문과 종결 검증 결과가 모두 일치해야 통과한다. 검색 지표와 원문 무결성 지표를 독립적으로 읽을 수 있다. 수동 기술평가, 모델 최종 답변 정확도, 실제 이용자의 만족도는 이 수치에서 도출할 수 없다.

각 출력에는 문항별 반환 ID·순위, 원문 대조 해시, 개발·보류군별 지표, 분야별 분모와 Hit@3, 최초 조회 시간 및 이후 조회 p50/p95가 있다. 지연 시간은 질의당 관측값 하나로 계산한다. 첫 관측에는 모델 자산 다운로드·벡터 캐시 등이 영향을 줄 수 있다. 첫 관측을 별도로 기록하며 개발군을 실행한 뒤 보류군을 연 경우 보류군 첫 행에도 이미 캐시가 있을 수 있다. 로컬 모델 로딩 시간이나 ChatGPT가 최종 답변을 생성하는 시간은 검색 타이머에 포함하지 않는다. 부하 검사는 별도다. 로컬·운영 보고서의 `corpusSha256`은 사례 ID 정렬 후 제목·기관·분야·감사 연도·색인 본문으로 계산한 동일 방식의 SHA-256이다. 두 자료의 동일성을 확인하려면 두 보고서의 이 값을 비교한다. 운영 서버가 수록 해시를 제공하지 않으면 평가가 중단된다. 목표 기준값은 첫 측정 전에 정했고 한 항목이라도 미달하면 종료 코드는 1이다.

## 예산 MCP 검증과 범위 대조

| 예산 MCP에서 사용한 방법 | 감사 MCP에서 확인하는 위치 |
|---|---|
| 기관·연도 정책, 실제 원문으로 검색·최종 검증 | 기존 `harness.mjs` 28항목이 기관·연도 필터, 13개 고정 사례, 다른 처분의 쪽 도용·문서 변조를 시험한다. |
| 골든 검색의 로컬/운영 반복, 개발군·보류군과 입력 해시 | 이 벤치마크가 같은 질문과 판정표로 용어 검색·의미 재정렬·공개 MCP를 시험한다. |
| 실행별 결과·오답과 독립된 공식 근거 기록 | `--output`에 실행 시각, 버전, 입력 해시, 결과·근거 해시·검색 시간·합격선별 결과를 저장한다. |
| 예산 총액·회계·추경·부서 이관·계산식 검산 | 감사 검색에서는 사건 귀속, 감사 연도, 처분요구 위치·문구를 대조한다. 예산 숫자 집계용 검산은 적용 대상이 다르다. |
| 후속 대화와 최종 답변 채점 | 별도 `npm run benchmark:answers`가 사전에 고정한 대화·판정표와 첫 답변을 연결해 인용, 정확성, 실무 유용성을 평가한다. 대화별·턴별 분모와 검색 순위의 분모를 구분한다. [답변 평가 자료](../benchmarks/answer) |
| 이용자 만족도와 첨부 문서 OCR | 검색 순위와 별도 답변 평가 결과로 실사용자 만족도나 OCR 판독 정확도를 산출할 수 없다. |

지표 설계에는 첫 관련 문서 순위를 사용하는 TREC 평가와 희소·밀집 검색을 비교한 BEIR 연구를 참고했다. [NIST TREC Deep Learning Track](https://trec.nist.gov/pubs/trec29/papers/OVERVIEW.DL.pdf) · [BEIR 논문](https://arxiv.org/abs/2104.08663)

외부 과학 질문에 포함된 ‘진동’과 사건을 특정하지 않은 ‘이 건도’가 과거에는 감사사례를 끌어왔다. 두 오류에 각각 재현 검사를 추가했다. 짧은 단독 주제 검색은 보존하며, 여러 개념 중 짧은 동음이의어 하나만 일치할 때와 내용 없는 지시어의 검색을 구별한다.

최종 회귀에서 알려진 근거가 상위 세 건에 표시된 문항은 두 방식 모두 30/32다. 첫 번째에 나온 문항은 용어 검색 24/32, 의미 재정렬 23/32다. 개발군의 수기 차량운행일지 일괄 결재와 보증금 통합계좌 이자 산정 문항은 두 방식 모두 지정 사례가 상위 다섯 건에 들지 않았다. 다른 차량운행일지·보증 사례가 검색되므로 두 문항의 실제 답변 적합성은 별도로 확인할 대상이다.

## 추가 예비군 첫 측정

기존 40문항에서 발견한 두 오류를 고친 뒤, 기존 하네스와 겹치지 않는 12개 분야의 공식 사례 12건과 결과를 비워야 하는 질문 4건을 별도로 고정했다. 사례 ID·출처·인용과 첫 질문을 분리했고 같은 사전 합격선을 적용했다. 다음은 로컬의 동일 시청 자료 1,717건으로 이 예비군을 처음 연 결과다. [예비 질문](../benchmarks/reserve-v1/questions.json) · [공식 근거 판정표](../benchmarks/reserve-v1/judgments.json)

| 검색 방식 | 첫 번째 | 상위 3건 | 상위 5건 | MRR@5 | 기권 | 원문 |
|---|---:|---:|---:|---:|---:|---:|
| 용어 | 8/12 | 10/12 | 11/12 | 0.771 | 3/4 | 12/12 |
| 용어+의미 재정렬 | 9/12 | 10/12 | 12/12 | 0.833 | 3/4 | 12/12 |

두 방식 모두 R16에서 **기권 기준 4/4를 충족하지 못했다**. 바이올린 활의 송진 양이 배음에 미치는 영향을 묻자 콘서트홀 카페 사업·건설사업 품질관리·공사기간 연장 사례가 나왔다. 이들 보고서에는 ‘영향을 미치다’처럼 질의와 우연히 겹치는 표현이 있다. 음악적 질문에 답할 근거는 없으므로 세 건은 오탐으로 채점했다. 이후 같은 예비군으로 개선을 확인한 값은 회귀 성적으로 기록한다. [첫 측정의 실제 반환 ID와 실행 기록](../benchmarks/run-history.json)

## R16 수정 후 로컬 회귀

이미 확인한 R16을 포함해 예비군 16문항을 다시 실행했다. 두 검색 방식 모두 R16에서 빈 결과를 반환해 기권이 3/4에서 4/4로 올랐다. 양성 문항의 상위 3건 적중은 양쪽 모두 10/12, 상위 5건 적중은 용어 검색 11/12와 의미 재정렬 12/12였다. 원문은 양쪽 모두 12/12건 일치했다.

기존 개발·보류군 40문항도 같은 코드로 다시 실행했다. 상위 3건 적중은 두 방식 모두 30/32, 기권은 8/8, 원문은 32/32였다. 두 회귀 실행 모두 원래 합격선을 통과했다. [최종 로컬 보고서별 SHA-256과 결과](../benchmarks/run-history.json)
